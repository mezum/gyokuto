# typed-vm 要件定義

Rust 風の trait ベースで静的型付けされた、Rust アプリ組み込み向けスクリプト言語。
JIT は持たず、バイトコードインタプリタで実行する。

## 1. 用途

- Rust アプリ (ゲーム・ツール等) に組み込むスクリプト言語
- ホストからスクリプト関数を呼び、スクリプトからホスト関数・ホスト型を利用する
- CLI ランナーは必須ではない (動作確認用に最小限を用意する程度)

## 2. 型システム

- 静的型付け。型推論は Rust 相当
  - 関数シグネチャは注釈必須
  - 関数内の `let` やクロージャ引数は局所的に推論
- struct / enum (代数的データ型) / tuple / 配列 / プリミティブ型
- trait と `impl Trait for T` による振る舞いの定義
- ジェネリクスはハイブリッド方式
  - 通常のジェネリクスは単相化し、型ごとにバイトコードを生成する
  - `dyn Trait` は vtable による動的ディスパッチ
- 関数・クロージャは第一級の値として変数に束縛できる

## 3. 型の値化とリフレクション

- 型をコンパイル時・実行時の両方で値として扱える
  - コンパイル時: 型を引数に取り型を返す関数などをコンパイル時に評価できる (Zig の comptime 相当)
  - 実行時: `Type` 値 (TypeInfo) を変数に束縛できる
- TypeInfo から取得できる情報
  - 型名・サイズ・アラインメント
  - フィールド一覧 (名前・型・オフセット)
  - enum のバリアント一覧
  - 実装している trait・メソッド一覧
  - 属性 (`#[...]`) 情報
- 関数値からもシグネチャ (引数・戻り値の型) を取得できる
- `dyn Any` 相当で型 ID による動的なダウンキャストができる

## 4. メモリモデル・RAII

- 所有権と move セマンティクス。借用チェッカー・ライフタイムは持たない
- 値はスコープを抜けた時点で決定的に `Drop` される (RAII)
- `Copy` な型 (プリミティブ等) 以外は代入・引数渡しで move、複製は明示的に `clone()`
- 参照は第二級参照とする
  - `&T` / `&mut T` は関数引数にのみ使用でき、変数・フィールドへの保存や戻り値にはできない
  - これによりライフタイム無しでダングリングを防ぐ
  - 同一値への `&mut` と `&` の同時渡しはコンパイルエラー
- 共有所有は標準ライブラリの `Rc<T>` / `Weak<T>` で行う (循環参照はリークする)
- ヒープ確保は `Box<T>` / `Vec<T>` / `String` / `HashMap<K, V>` 等で明示する
- クロージャ
  - 値として保存・返却するクロージャは常に move キャプチャ
  - 引数として直接渡し、呼び出し中にのみ使うクロージャは参照キャプチャ可

## 5. 値のレイアウトと最適化

- 構造体はフラットな値型として、スタックフレームやヒープ上にインライン配置する
  - ネストした構造体も埋め込み、Rust / C と同等のレイアウトとする
- 型が静的に確定しているフィールドアクセスは、オフセット指定の単一命令でロード / ストアする
- 型が確定しない場合 (リフレクション・`dyn`) は TypeInfo のオフセットを用いる
- ホスト型とメモリレイアウトを一致させ、ゼロコピーでやり取りできる

## 6. エラー処理

- `Result<T, E>` / `Option<T>` と `?` 演算子
- `panic` はスクリプトの実行を中断し、ホストには `Err` として返す (ホストは落ちない)
- panic 時もスタック上の値は `Drop` される

## 7. シリアライズ

- serde 連携: スクリプトの値を TypeInfo 経由で `Serialize` / `Deserialize` に橋渡しする
  - フォーマット (JSON 等) はホストが選ぶ
- スクリプト内でもリフレクション API を使ってシリアライザを実装できる

## 8. ホスト連携

- ホスト関数の登録: Rust の関数をスクリプトから呼べる (引数・戻り値は型チェックされる)
- ホスト型の公開: derive マクロ等で Rust の struct をスクリプトの型として公開し、フィールドへ直接アクセスする
- 実行制限: 命令数 (fuel)・メモリ使用量の上限を設定でき、超過時は中断する
- ホットリロード: 実行中にスクリプトの関数を差し替えられる
  - 状態はホスト側が保持する。必要ならシリアライズ → デシリアライズで移行する
  - 生きている値のレイアウト自動マイグレーションは行わない
- VM インスタンスは `Send` で、別スレッドで実行できる。複数 VM を並列に動かせる
- コルーチン: スクリプトは `yield` でホストに制御を戻し、後で再開できる

## 9. バイトコード

- コンパイル済みバイトコードをファイルに保存・配布できる
- ファイルにはフォーマットのバージョンを持たせ、非互換なものはロードを拒否する
- ロード時に検証 (verify) を行い、型安全性を破るバイトコードを拒否する

## 10. 開発者向けツール

- MVP: ソース位置付きの分かりやすいエラー表示 (ariadne / miette 等の既存ライブラリを利用)
- MVP 後に 1 つずつ実装する
  - LSP (補完・型表示・診断)
  - デバッガ (ブレークポイント・ステップ実行)

## 11. 対象外 (Non-goals)

- JIT コンパイル
- 借用チェッカー・ライフタイム
- GC
- スクリプト内でのスレッド生成 (Send / Sync 相当)
- ホットリロード時の状態の自動マイグレーション
- REPL (MVP 後に検討)

## 12. 未決事項

- 構文の詳細 (Rust 構文にどこまで寄せるか)
- モジュールシステム・ファイル分割の単位
- 整数オーバーフロー時の挙動 (panic / wrap)
- 文字列のエンコーディング (UTF-8 前提で良いか)
- マクロの有無
- コンパイル時評価で許可する操作の範囲 (ヒープ確保・ホスト関数呼び出しの可否)
- VM 方式 (レジスタ型 / スタック型) は実装フェーズで決定
- デバッガのプロトコル (DAP を想定)
